这篇文章不是命令大全，而是一份按使用频率安排的手册：**先学每天用得到的，再按需要查进阶和冷门功能。** 每个示例都可以复制；代码框里的内容是写法，代码框外的内容才会参与排版。

## 先分清：Markdown 和 LaTeX 各自做什么

Markdown 负责文章结构：标题、段落、列表、链接、图片和代码。LaTeX 本来是一套完整的文档排版系统；在这个博客里，我们使用的是它的**数学公式语法**，由 KaTeX 显示，不是完整的 LaTeX 编译环境。

所以，这里可以写分式、矩阵和积分，但不能直接贴一份含有 `\documentclass`、`\usepackage`、`\begin{document}` 的论文源文件，期待它变成论文。TikZ 绘图、参考文献管理、自动交叉引用等也不能视为现成支持。

学习顺序建议：先读 Markdown 的前三节，再读 LaTeX 的前三节。其余部分用到时再查，不需要一次背完。

## 一、Markdown 最常用：把文字写清楚

### 1. 标题：用层级组织文章

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

`#` 越多，标题层级越深，最多六级。符号后留一个空格，标题前后留空行。

这个博客的标题已经有单独的输入框，正文通常从 `##` 开始即可。不要为了让字变大随意跳级：二级标题下接三级标题，比一会儿一级、一会儿四级更利于阅读和生成大纲。

### 2. 段落与换行：空一行，比连按回车可靠

```markdown
这是第一段，可以写很多句话。

这是第二段，段落之间空一行。
```

普通的单次回车在不同编辑器里不一定显示为换行；本博客的发布渲染配置不会把每次回车都强制变成换行。写文章时优先用空行分段，不要靠空格“推”出缩进。

如果确实要在同一段内换行，常见写法是在行末加两个空格再回车。由于末尾空格看不见、也可能被编辑器清理，普通文章仍建议分段；诗歌等特殊排版要检查发布后的效果。

### 3. 强调：粗体最实用，别让整段都变粗

```markdown
这是 **重点**。
这是 *斜体*。
这是 ***粗斜体***。
这是 ~~已经不适用的说法~~。
```

效果：**重点**、*斜体*、***粗斜体***、~~已经不适用的说法~~。

删除线属于常见扩展，并非所有 Markdown 引擎都支持。中文长段落通常不必大量使用斜体；把真正重要的短语加粗，就已经足够。

### 4. 列表：列举用无序，步骤用有序

```markdown
- 今天学到的概念
- 尚未解决的问题
- 下一步的安排

1. 打开写作工作台
2. 输入标题和正文
3. 等待云端保存
4. 确认后发布
```

不要用手打的 `①②③` 代替所有有序列表。真正的列表更容易调整顺序，也更利于编辑器识别结构。

### 5. 链接：给链接一个有意义的名字

```markdown
[返回我的博客](https://sleepy-m.github.io/)
```

效果：[返回我的博客](https://sleepy-m.github.io/)。

方括号里是显示文字，圆括号里是地址。相比“点击这里”，用“查看实验记录”这样的描述更清楚。带空格的地址最好先进行 URL 编码，避免链接被截断。

### 6. 图片：只比链接多一个感叹号

```markdown
![图片的简短说明](/uploads/example.png)
```

`example.png` 只是语法占位符，不是这篇文章附带的图片。实际写作时使用工具栏上传图片，不必手写路径。

方括号内是替代文本，用来说明图片内容，不保证显示成图片下方的图注。需要图注时，在下一段另写说明最通用。不要写电脑上的 `C:\Users\...` 路径：别人无法访问你的本地硬盘。

### 7. 行内代码和代码块

一句话里提到命令、文件名或变量，用一对反引号：

```markdown
运行 `python main.py`，并检查 `result.txt`。
```

多行代码用围栏，开头标注语言：

````markdown
```python
def square(x):
    return x * x

print(square(3))
```
````

语言名常见的有 `python`、`cpp`、`javascript`、`bash`、`json`、`yaml`；纯文本可用 `text`。语言名影响高亮，不会执行代码。代码示例中包含三反引号时，外层可以使用四反引号，正如上面的示例。

## 二、Markdown 常用进阶：让笔记更有条理

### 8. 引用：补充说明，而不是装饰每一段

```markdown
> 先把内容写清楚，再考虑排版。
>
> 这是同一个引用中的第二段。
```

> 先把内容写清楚，再考虑排版。

引用也可以嵌套：在行首写 `>>`。但层级太多会压缩正文宽度，手机上尤其明显。

### 9. 表格：用于比较，不用于强行布局

```markdown
| 项目 | 写法 | 使用频率 |
| :--- | :---: | ---: |
| 标题 | 井号 | 很高 |
| 粗体 | 双星号 | 很高 |
| 表格 | 竖线 | 中等 |
```


| 项目 |  写法  | 使用频率 |
| :--- | :----: | -------: |
| 标题 |  井号  |     很高 |
| 粗体 | 双星号 |     很高 |
| 表格 |  竖线  |     中等 |

分隔行中的冒号控制对齐：左边冒号是左对齐，两边冒号是居中，右边冒号是右对齐。表格适合短内容，长段落建议改用小标题。单元格中的字面量竖线写作 `\|`；表格里的复杂公式或代码尤其要留意竖线冲突。

### 10. 嵌套列表：用缩进表达从属关系

```markdown
- 学习笔记
    - Markdown
    - 数学公式
- 项目记录
    - 实验过程
    - 结果分析
```

四个空格是常见、直观的嵌套写法，但严格来说缩进量还与上一级列表标记宽度有关。有序列表编号很长时，应让子内容对齐父项正文的起始位置。不要混用制表符和空格。

### 11. 分隔线

```markdown
上一部分的结尾。

---

下一部分的开头。
```

分隔线上下留空行，避免与另一种标题语法混淆。一篇文章放一两条即可，过多会打断阅读。

### 12. 转义：想显示符号本身怎么办

```markdown
\*这不是斜体\*
\# 这不是标题
\[这不是链接\]
```

反斜杠可以让不少标点不再参与 Markdown 解析。如果是在介绍语法，直接使用行内代码或代码块通常更清楚。注意：代码块内不需要为了 Markdown 再加一层转义。

## 三、Markdown 较冷门与扩展：知道即可，先确认支持

### 13. 引用式链接：长文里重复引用时很方便

```markdown
可以阅读 [KaTeX 文档][math-doc]，也可以把 [函数列表][math-doc] 收藏起来。

[math-doc]: https://katex.org/docs/supported.html
```

把地址集中放在文末，正文更干净，修改一次即可更新多个引用。这里的“引用式链接”不是脚注。

### 14. 任务清单：常见，但不是基础语法

```markdown
- [ ] 整理笔记
- [x] 核对公式
- [ ] 发布文章
```

有些编辑器会把它显示为复选框。**编辑器能预览，不代表发布引擎一定会生成同样的复选框**；本博客当前没有显式配置任务清单插件，因此先当作写作清单使用，发布样式需另行验证。它也不是自动管理项目进度的数据库。

### 15. 脚注：适合补充，不适合堆满正文

```markdown
这里有一个需要补充的概念。[^note]

[^note]: 这是一条补充说明。
```

脚注是扩展语法。本博客当前没有显式配置脚注插件，不能保证发布后变成可点击脚注。需要通用方案时，用文末“注释”小节配合编号。

### 16. 折叠内容、HTML 与平台专属语法

```html
<details>
<summary>展开查看补充内容</summary>

这里是补充说明。

</details>
```

这依赖 HTML 支持及编辑器的安全过滤规则，内部 Markdown 是否继续解析也因实现而异。它不是所有平台通用的 Markdown 功能。本博客发布端允许 HTML，但工作台会进行安全过滤，仍须检查两端效果。

类似 `==高亮==`、`[TOC]`、`::: warning`、GitHub 的提示块、Mermaid 流程图，都不能因为某个网站支持，就默认这里支持。尤其不要把 Mermaid 代码块当作一定能渲染的图；未配置时，它只是普通代码。

### 17. 不太常见的标题与代码写法

标题也可以在文字下方写 `===` 或 `---`；代码也可以用整段缩进来表示。但这些写法容易与分隔线、列表缩进混淆。日常统一用 `##` 标题和围栏代码块，后期维护更轻松。

## 四、LaTeX 最常用：先会写一行公式

### 1. 行内公式与独立公式

行内公式跟着一句话走：

```latex
质能关系为 $E=mc^2$。
```

质能关系为 $E=mc^2$。

较长公式单独成行，两个美元符号最好各占一行，公式块前后空一行：

```latex
$$
E=mc^2
$$
```

$$
E=mc^2
$$

本博客采用这两种美元符号分隔方式。其他平台可能使用 `\(...\)`、`\[...\]`，不要假设不同分隔符在这里都被插件识别。写金额时若误触公式解析，可以在代码形式中写 `$100`，或改写为“100 美元”。

### 2. 上下标：花括号是最重要的习惯

```latex
x^2, x_i, x_{ij}, x^{n+1}, a_1^2
```

$$
x^2,\quad x_i,\quad x_{ij},\quad x^{n+1},\quad a_1^2
$$

`^` 是上标，`_` 是下标。不加花括号时通常只作用于紧随其后的一个符号：`x^10` 不等于 `x^{10}`。只要上下标超过一个字符，就加 `{}`。

### 3. 分数、根号与括号

```latex
\frac{a+b}{c}, \sqrt{x}, \sqrt[3]{x}, \left(\frac{a}{b}\right)
```

$$
\frac{a+b}{c},\quad \sqrt{x},\quad \sqrt[3]{x},\quad \left(\frac{a}{b}\right)
$$

`\frac` 后两个分组依次是分子、分母；`\sqrt[3]` 是三次根。`\left` 与 `\right` 会调整括号大小，必须成对；只需要单侧括号时，可以用点作为不显示的一侧，例如 `\left. f(x)\right|_0^1`。

### 4. 乘除、比较与常用希腊字母


| 想写的符号         | 命令                                           |
| ------------------ | ---------------------------------------------- |
| 乘号、点乘符号     | `\times`、`\cdot`                              |
| 除号、正负号       | `\div`、`\pm`                                  |
| 不等于、约等于     | `\ne`、`\approx`                               |
| 小于等于、大于等于 | `\le`、`\ge`                                   |
| 无穷大             | `\infty`                                       |
| α、β、γ、δ     | `\alpha`、`\beta`、`\gamma`、`\delta`          |
| θ、λ、μ、σ、ω | `\theta`、`\lambda`、`\mu`、`\sigma`、`\omega` |
| Δ、Σ、Ω         | `\Delta`、`\Sigma`、`\Omega`                   |

例如：

$$
\alpha+\beta\le\pi,\qquad a\times b\ne a+b
$$

命令区分大小写。不是每个拉丁字母名称都能通过加反斜杠变成希腊字母，也不是所有希腊字母都有独立的大写命令。

### 5. 函数名与公式中的文字

```latex
\sin x, \cos x, \tan x, \log x, \ln x, \exp(x)
```

数学变量通常用斜体，函数名应使用命令。`sin x` 会被当成三个变量相乘的样子；`\sin x` 才是规范的正弦函数排版。

说明文字用 `\text{}`：

$$
v=\frac{s}{t},\qquad \text{其中 }t>0
$$

中文会使用相应的文字字体，并非所有数学字体命令都能把中文变成同样的样式。

## 五、LaTeX 常用进阶：课程与技术笔记够用了

### 6. 求和、乘积、极限

```latex
\sum_{i=1}^{n} i=\frac{n(n+1)}{2}
\prod_{i=1}^{n} a_i
\lim_{x\to 0}\frac{\sin x}{x}=1
```

$$
\sum_{i=1}^{n} i=\frac{n(n+1)}{2},\qquad
\prod_{i=1}^{n}a_i,\qquad
\lim_{x\to 0}\frac{\sin x}{x}=1
$$

独立公式与行内公式中的上下限位置可能不同，这是数学排版方式的差别，不一定是写错了。行内公式过高、过长会破坏行距，移到独立公式通常更好。

### 7. 积分、导数与偏导数

```latex
\int_0^1 x^2\,\mathrm{d}x=\frac{1}{3}
\frac{\mathrm{d}y}{\mathrm{d}x}
\frac{\partial f}{\partial x}
```

$$
\int_0^1 x^2\,\mathrm{d}x=\frac{1}{3},\qquad
\frac{\mathrm{d}y}{\mathrm{d}x},\qquad
\frac{\partial f}{\partial x}
$$

`\,` 在被积函数与微分之间加入小间距；`\mathrm{d}` 让微分符号使用正体。它们影响排版，不替你计算结果。

### 8. 多行推导与对齐

```latex
\begin{aligned}
(a+b)^2 &= a^2+2ab+b^2 \\
        &= (a-b)^2+4ab
\end{aligned}
```

$$
\begin{aligned}
(a+b)^2 &= a^2+2ab+b^2 \\
        &= (a-b)^2+4ab
\end{aligned}
$$

把上面的环境放在 `$$` 内。`&` 标记对齐位置，`\\` 表示公式内部换行。不要把 Markdown 普通换行、公式里的 `\\` 和代码字符串中的转义混为一谈。

### 9. 分段函数

```latex
f(x)=\begin{cases}
x^2, & x\ge 0, \\
-x, & x<0.
\end{cases}
```

$$
f(x)=\begin{cases}
x^2, & x\ge 0, \\
-x, & x<0.
\end{cases}
$$

左边是表达式，右边是条件。不要忘记 `\end{cases}`，环境名称也必须前后一致。

### 10. 矩阵、向量与范数

```latex
A=\begin{bmatrix}
1 & 2 \\
3 & 4
\end{bmatrix}
```

$$
A=\begin{bmatrix}1&2\\3&4\end{bmatrix},\qquad
\mathbf{x}=\begin{bmatrix}x_1\\x_2\end{bmatrix}
$$

矩阵中 `&` 分列，`\\` 分行。`matrix` 没有外括号，`pmatrix` 使用圆括号，`bmatrix` 使用方括号，`vmatrix` 使用单竖线。

向量可以写 `\vec{v}` 或 `\mathbf{v}`；粗体希腊字母可用 `\boldsymbol{\theta}`。这些是记号选择，不意味着对象会被自动识别成向量。

$$
\vec{v},\quad \mathbf{v},\quad \boldsymbol{\theta},\quad
\lVert\mathbf{x}\rVert_2=\sqrt{x_1^2+x_2^2}
$$

范数优先使用 `\lVert` 和 `\rVert`，比在 Markdown 表格里反复输入竖线更不容易产生冲突。

### 11. 集合、逻辑与概率

```latex
x\in\mathbb{R},\quad A\subseteq B,\quad A\cup B,\quad A\cap B
\forall x,\quad \exists y,\quad P\Rightarrow Q,\quad P\iff Q
P(A\mid B)=\frac{P(A\cap B)}{P(B)}
```

$$
x\in\mathbb{R},\quad A\subseteq B,\quad A\cup B,\quad A\cap B
$$

$$
P(A\mid B)=\frac{P(A\cap B)}{P(B)},\qquad P(B)>0
$$

集合差用 `\setminus`，空集用 `\varnothing`，不属于用 `\notin`。条件概率中的 `\mid` 提供合适的间距，不必用键盘竖线硬凑。

### 12. 单位、角标和常见工程记号

```latex
v=3\,\mathrm{m/s},\quad \theta=30^\circ
\hat{x},\quad \bar{x},\quad \dot{x},\quad \ddot{x}
```

$$
v=3\,\mathrm{m/s},\quad \theta=30^\circ,\quad
\hat{x},\quad \bar{x},\quad \dot{x},\quad \ddot{x}
$$

单位建议用正体，与变量区分；下标是文字说明时也可以用 `\text{}`，例如 `v_{\text{max}}`。点号常用于时间导数，帽子常用于估计量，但具体含义必须在文章里自己定义。

## 六、LaTeX 较冷门：需要时再查的排版工具

### 13. 上下括号与标注

```latex
\underbrace{x_1+\cdots+x_n}_{n\text{ 项}}
\overset{\text{定义}}{=}
\boxed{E=mc^2}
```

$$
\underbrace{x_1+\cdots+x_n}_{n\text{ 项}},\qquad
a\overset{\text{定义}}{=}b,\qquad \boxed{E=mc^2}
$$

`\underbrace` 在下方加括号说明，`\overbrace` 在上方；`\overset` 把标记放到符号上方。方框适合标记最终结论，不必给每个等式都加框。

### 14. 自定义运算符与字体

```latex
\operatorname{rank}(A),\quad \operatorname{diag}(a,b)
\mathcal{L},\quad \mathbb{R},\quad \mathrm{T},\quad \boldsymbol{\alpha}
```

$$
\operatorname{rank}(A),\quad \operatorname{diag}(a,b),\quad
\mathcal{L},\quad \mathbb{R},\quad \mathrm{T},\quad \boldsymbol{\alpha}
$$

`\operatorname` 适合不在内置函数命令中的运算名称；`\mathcal` 常用于花体大写字母，`\mathbb` 常用于数集。字体可用字符范围受渲染器与字体限制，并不是任意文字都能变成花体。

### 15. 间距和字号控制

常见间距由小到大有 `\,`、`\:`、`\;`、`\quad`、`\qquad`；`\!` 用于收紧间距。通常先让数学引擎自动处理，只有确实拥挤或语义需要分隔时再调整。

`\dfrac{a}{b}` 使用较大的分数样式，`\tfrac{a}{b}` 使用较紧凑的样式。不要为了显眼把段落中的每个分数都放大，读起来会忽高忽低。

### 16. 组合数、行列式与省略号

```latex
\binom{n}{k}=\frac{n!}{k!(n-k)!}
\det A,\quad \ldots,\quad \cdots,\quad \vdots,\quad \ddots
```

$$
\binom{n}{k}=\frac{n!}{k!(n-k)!}
$$

`\ldots` 是靠下的横向省略号，`\cdots` 在中间，`\vdots` 竖排，`\ddots` 对角排，矩阵中常会用到。不要用随手敲出的三个句点代替所有数学省略号。

### 17. 手工编号与宏：有用，但不建议刚入门就依赖

部分渲染器允许用 `\tag{1}` 手工标记公式，但这不是完整的自动编号与交叉引用系统。本博客不承诺 `\label`、`\ref`、`\eqref` 在不同公式块之间自动关联。

宏定义如 `\newcommand` 的支持范围、作用域和安全限制也随渲染环境变化。为了让文章更容易迁移，博客中的公式尽量独立可读；重复命令多写几次，通常比依赖一套隐藏宏更稳妥。需要正式论文功能时，应使用完整的 LaTeX 项目。

## 七、把两种语法放在一起：一段完整的技术笔记

下面是可以直接复制到新草稿的示例。围栏中的内容是整段 Markdown 源码：

````markdown
## 用均值描述一组测量

假设有 $n$ 次测量，结果为 $x_1,\ldots,x_n$。
样本均值定义为：

$$
\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i
$$

### 示例数据

| 次数 | 测量值 |
| --- | ---: |
| 1 | 2 |
| 2 | 4 |
| 3 | 6 |

因此 $\bar{x}=4$。

```python
values = [2, 4, 6]
mean = sum(values) / len(values)
print(mean)
```

> 均值不等于每一次测量值，也不自动代表测量误差。
````

这段文字的结构是：标题说明主题，普通段落说明背景，公式给出定义，表格给出数据，代码提供计算方式，引用补充边界。清楚的结构，比堆砌复杂语法更重要。

## 八、最容易踩的坑与排查顺序

### 公式没有显示，而是原样出现

先看公式是不是放进了代码框或行内代码；代码里的公式本来就不应渲染。再检查美元符号是否成对，独立公式前后是否空行，以及有没有把美元符号写成全角字符。

### 公式显示红色或提示错误

按这个顺序检查：

1. `{}` 是否配对，命令是否拼错。
2. `\begin{...}` 与 `\end{...}` 是否一致。
3. `\left` 与 `\right` 是否配对。
4. 多行环境是不是少了 `&` 或 `\\`。
5. 命令是否需要完整 LaTeX 宏包，而 KaTeX 并不支持。

先删到只剩最短公式，再一点点加回来，比盯着一大段猜错误快得多。

### 从程序里复制后出现很多反斜杠

Markdown 正文里写分数是 `\frac{a}{b}`，不是 `\\frac{a}{b}`。但在 JSON 或某些编程语言字符串里，为了表达一个反斜杠，源代码可能需要写两个。这是字符串转义，与 LaTeX 语法不是同一层问题。只有公式环境中真正要换行时才用 `\\`。

### 编辑器里能看，发布后不一样

工作台与博客发布端使用不同的渲染链路。基础语法优先，扩展语法逐项确认。脚注、任务框、HTML 折叠、流程图、公式编号等尤其不能只看编辑器预览。

### 表格破了、列表不缩进

检查表格单元格是否出现未转义的竖线，列表前后是否空行，嵌套层级是否正确缩进。不要在普通段落开头随意加四个空格，否则可能被当成代码。

### 写得出来，但手机上很难读

长公式拆成多行推导，宽表格拆成两张，代码按合理位置换行。公式和表格都不是越长越专业，能在手机上读懂同样重要。

## 九、一页速查：先记住这些就够了


| 需求           | 写法                                |
| -------------- | ----------------------------------- |
| 二级、三级标题 | `## 标题`、`### 标题`               |
| 新段落         | 空一行                              |
| 强调、代码     | `**重点**`、反引号包围代码          |
| 列表           | `- 项目`、`1. 步骤`                 |
| 链接、图片     | `[文字](地址)`、`![说明](图片地址)` |
| 引用           | `> 说明`                            |
| 代码块         | 三反引号围栏，可标语言名            |
| 行内、独立公式 | `$...$`、独占行的 `$$` 围栏         |
| 上下标         | `x^{n+1}`、`x_{ij}`                 |
| 分式、根号     | `\frac{a}{b}`、`\sqrt{x}`           |
| 求和、积分     | `\sum_{i=1}^{n}`、`\int_a^b`        |
| 公式文字       | `\text{说明}`                       |
| 多行对齐       | `aligned` 环境，`&` 对齐、`\\` 换行 |
| 分段、矩阵     | `cases`、`bmatrix` 环境             |

最后记住一个原则：**格式服务于表达。先把想法写下来，再用最少的语法把它整理清楚。**
